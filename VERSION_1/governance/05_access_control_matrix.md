# Access Control Matrix (RBAC)

**Версия:** 1.0 (Draft)  
**Область:** Lakehouse (RAW/STAGE/MART), Airflow, Trino, Superset  
**Принцип:** Минимальные привилегии (least privilege)  
**Статус:** Проект документа *(Примечание: в текущем учебном проекте формальный RBAC и управление пользователями не реализованы, но матрица спроектирована как эталон для продакшен-среды).*

---

## 1. Роли

| Роль | Описание | Состав |
|------|----------|--------|
| **Data Analyst** | Аналитика, построение витрин, исследования | Участники буткемпа, аналитики |
| **Data Engineer** | Разработка ETL, поддержка pipeline | Команда Data Engineering |
| **Data Scientist** | Обучение ML-моделей, эксперименты | Команда ML |
| **ML Engineer** | Внедрение и мониторинг моделей | Команда ML Ops |
| **BI Consumer** | Просмотр дашбордов Superset | Бизнес-пользователи, заказчики |

## 2. Матрица доступа к данным (Lakehouse)

| Ресурс | Data Analyst | Data Engineer | Data Scientist | ML Engineer | BI Consumer |
|--------|--------------|---------------|----------------|-------------|-------------|
| **RAW** (Iceberg) | READ | READ/WRITE | READ | READ | — |
| **STAGE** (Iceberg) | READ | READ/WRITE | READ | READ | — |
| **MART** (Iceberg) | READ | READ/WRITE | READ | READ | READ |
| **Quarantine tables** | — | READ/WRITE | — | — | — |
| **Airflow DAGs** | — | READ/WRITE | — | READ | — |
| **Airflow Variables/Connections** | — | WRITE (секреты) | — | READ | — |
| **Trino** | READ (MART) | READ/WRITE | READ | READ | READ (MART) |
| **Superset** | READ | READ | READ | READ | READ/WRITE (дашборды) |
| **Marquez (lineage)** | READ | READ/WRITE | READ | READ | READ |
| **Iceberg snapshots** | READ | READ/WRITE | READ | READ | READ |

**Легенда:** READ — чтение, WRITE — запись/изменение, — — нет доступа.

## 4. Поля с PII — ограничения

| Поле | Таблица | Кто имеет доступ | Ограничения |
|------|---------|------------------|-------------|
| `personaname` | `players` | Data Engineer, Data Scientist | Не выгружать в открытом виде вне платформы. В учебном проекте шифрование не реализовано, но в продакшене требуется. |
| `account_id` | `players`, `match_players` | Все роли с доступом к данным | Псевдонимизировано, не связывать с реальными лицами без согласия. |
| `steam_account_id` | Mongo коллекции | Data Engineer, Data Scientist | Только внутри Iceberg/Spark. |

---

## 5. Процедура предоставления доступа (Эталон для продакшена)

1. Запрос доступа через трекер задач.
2. Одобрение владельцем ресурса (Data Engineering Lead для данных).
3. Предоставление минимально необходимого доступа.
4. Ежемесячный ревью прав доступа (access review).
5. Отзыв доступа при увольнении или изменении роли (не позднее 1 рабочего дня).

---

## 6. Мониторинг доступа (Эталон для продакшена)

- Логирование всех попыток доступа к RAW и PII-полям.
- Еженедельный обзор аномальных запросов (mass download, доступ вне рабочего времени).
- Алерт при попытке доступа без прав.

---

## 7. Исключения

Любое исключение из матрицы требует:
- Документированного обоснования.
- Одобрения Data Engineering Lead.
- Ограниченного срока действия (максимум 30 дней).
- Фиксации в журнале исключений.
