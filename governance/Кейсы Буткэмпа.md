# Практические кейсы

## 1. Влияние времени уничтожения и расположения башни от победы (сделан)
**Sankey-диаграмма:** время падения первой башни -> победа.

**Гипотеза:** чем раньше падает первая башня, тем выше шанс победы атакующей стороны.


## 2. Корреляция между временем и стороной first blood и победой


**Данные:**
- `kill_events` — первое убийство в матче (`MIN(time)`)
- `kill_events.attacker` — кто убил (по `hero_id` определяем `Radiant`/`Dire` через `match_players`)
- `matches.radiant_win`

**Гипотеза:** сторона, получившая first blood, выигрывает чаще. Если first blood после 5 мин — эффект слабее.

**Пример запроса:**
```sql
with fb as (
  select match_id,
    min(time) as fb_time,
    min(attacker) as fb_hero
  from iceberg.raw.mongo__kill_events
  group by match_id
)
select
  case
    when fb.fb_time < 120 then '0-2 min'
    when fb.fb_time < 300 then '2-5 min'
    when fb.fb_time < 600 then '5-10 min'
    else '10+ min'
  end as bucket,
  count(*) as matches,
  avg(case when m.radiant_win then 1 else 0 end) as radiant_winrate
from fb
join iceberg.raw.pg__matches m on fb.match_id = m.match_id
group by bucket order by bucket;
```

## 5. Распределение урона по башням между ролями

**Данные:**
- `tower_damage_events` — `attacker` (hero_id), `damage`
- `match_players` — `hero_id`, `account_id`, ну и косвенно через `gold_per_min` деление на кор/саппорт
- Позиция (`rank`) или статистика (GPM/XPM)

**Гипотезы:**
- Pos 1-2 наносят 70%+ урона башням
- Pos 5 наносит <5% урона башням
- Чем равномернее распределение урона между ролями, тем выше шанс победы (командная игра)

**Визуализация:** stacked bar chart по ролям для каждого матча.

**SQL:**
```sql
select
  case
    when mp.gold_per_min >= 600 then 'core (600+ gpm)'
    when mp.gold_per_min >= 400 then 'semi-core'
    else 'support (<400 gpm)'
  end as role,
  sum(d.damage) as total_dmg,
  count(*) as hits,
  count(distinct d.match_id) as matches
from iceberg.raw.mongo__tower_damage_events d
join iceberg.raw.pg__match_players mp
  on d.match_id = mp.match_id and d.attacker = mp.hero_id
where d.npc_id between 16 and 35
group by role order by total_dmg desc;
```

## 14. Предсказание победителя по ранним событиям (ML-классификация)

**Тип:** spark + ml (бинарная классификация)

**Данные:**
- Признаки из первых 15 минут матча:
  - `kill_events` — количество убийств на каждой стороне
  - `tower_damage_events` — урон по башням (суммарный, количество попаданий)
  - `gold_events` — суммарное золото (reason='PASSIVE', 'CREEPS')
  - `rune_events` — количество собранных bounty run
  - `cs_events` — last hits (isCreep=true, isNeutral=true) — только первые 15 мин
  - `death_events` — количество смертей
  - `heal_events` — суммарное лечение
  - `streak_events` — количество серий убийств
- Целевая: `matches.radiant_win`

**Гипотеза:** комбинация ранних признаков (0-15 мин) позволяет предсказать победителя с ~75%+ точностью.

**Pipeline (Spark):**
```python
from pyspark.ml.feature import VectorAssembler, StandardScaler
from pyspark.ml.classification import RandomForestClassifier
from pyspark.ml.evaluation import BinaryClassificationEvaluator

# Агрегируем признаки за первые 15 минут по каждому матчу
features = spark.sql("""
  select
    k.match_id,
    k.radiant_kills_15min,
    k.dire_kills_15min,
    t.radiant_tower_dmg,
    t.dire_tower_dmg,
    g.radiant_gold_15min,
    g.dire_gold_15min,
    c.radiant_lh_15min,
    c.dire_lh_15min,
    m.radiant_win as label
  from (
    select match_id,
      sum(case when steam_account_id in (select ...) then 1 else 0 end) as radiant_kills_15min,
      sum(case when steam_account_id in (select ...) then 1 else 0 end) as dire_kills_15min
    from iceberg.raw.mongo__kill_events where time < 900
    group by match_id
  ) k
  join ... t on k.match_id = t.match_id
  join ... g on k.match_id = g.match_id
  join ... c on k.match_id = c.match_id
  join iceberg.raw.pg__matches m on k.match_id = m.match_id
""")

assembler = VectorAssembler(
    inputCols=["radiant_kills_15min", "dire_kills_15min", "radiant_tower_dmg", ...],
    outputCol="features"
)
scaler = StandardScaler(inputCol="features", outputCol="scaled_features")
rf = RandomForestClassifier(featuresCol="scaled_features", labelCol="label")

pipeline = Pipeline(stages=[assembler, scaler, rf])
model = pipeline.fit(train)
```

**Feature importance:** Random Forest выдаёт топ признаков — какой фактор (kills, gold, tower damage)最有 влияние на победу.

**Метрики:** AUC-ROC, precision/recall, confusion matrix.

## 16. Обнаружение смурф-аккаунтов (аномалии)

**Тип:** spark + ml (обнаружение аномалий / бинкаунт)

**Данные:**
- `match_players` — усреднённая стата по `account_id` (KDA, GPM, XPM, win rate)
- `players` / `raw_players` — никнеймы
- `matches` — количество матчей, `duration`

**Гипотеза:** смурф-аккаунты отличаются аномально высокой статистикой (KDA > 5, GPM > 700, win rate > 65%) при малом количестве игр, часто с подозрительными никнеймами (набор символов)

**Метод:**
1. Агрегировать статистику по `account_id`:
   - Средний KDA
   - Средний GPM/XPM
   - Win rate
   - Количество матчей
   - Средняя длительность матчей
   - Список героев
2. **Isolation Forest** или **LOF (Local Outlier Factor)** для поиска аномалий
3. Дополнительно: частота смены ника (по `raw_players.loaded_at`)

```python
from pyspark.ml.feature import VectorAssembler, StandardScaler
from pyspark.ml.clustering import KMeans

player_stats = spark.sql("""
  select mp.account_id,
    avg((mp.kills + mp.assists) / greatest(mp.deaths, 1)) as avg_kda,
    avg(mp.gold_per_min) as avg_gpm,
    avg(mp.xp_per_min) as avg_xpm,
    avg(case when mp.win then 1.0 else 0.0 end) as win_rate,
    count(*) as matches_played,
    count(distinct mp.hero_id) as unique_heroes
  from iceberg.raw.pg__match_players mp
  group by mp.account_id
  having count(*) >= 5
""")

# Isolation Forest
from pyspark.ml.classification import RandomForestClassifier
# или используем KMeans с 2 кластерами (normal / smurf)
assembler = VectorAssembler(
    inputCols=["avg_kda", "avg_gpm", "avg_xpm", "win_rate", "matches_played", "unique_heroes"],
    outputCol="features"
)

kmeans = KMeans(featuresCol="scaled", k=2, seed=42)
```

## 18. Кластеризация стилей игры (ML-сегментация)

**Тип:** spark + ml (unsupervised clustering)

**Данные:**
- Вектор признаков на матч:
  - `tower_damage_events` — темп пуша (время первой башни, средний интервал)
  - `kill_events` — агрессивность (количество убийств до 15 мин, тотальное количество)
  - `rune_events` — контроль карты (количество собранных рун)
  - `ward_events` — вижн (количество поставленных вардов)
  - `cs_events` (`isNeutral`=true) — количество фарма нейтралов
  - `heal_events` — количество лечения
  - `matches.duration`

**Гипотеза:** можно выделить N кластеров игровых стилей:
1. **Спектр пуша** — ранние башни, мало убийств, быстрые игры
2. **Спектр файтов** — много убийств, мало фарма, нейтралов, постоянные драки
3. **Сбалансированный** — ровный темп, и убийства и фарм
4. **Лейт-спектр** — мало событий до 20 мин, длинные игры

**Метод:**
- Feature engineering через Spark SQL
- PCA для снижения размерности
- KMeans / DBSCAN для кластеризации
- Визуализация через t-SNE

```python
from pyspark.ml.clustering import KMeans
from pyspark.ml.feature import PCA
from pyspark.ml.evaluation import ClusteringEvaluator

# Собираем фичи по матчам
match_features = spark.sql("""
  select
    m.match_id,

    count(distinct we.time) as ward_count,
    avg(ke.gold) as avg_kill_gold,
    m.duration

  left join iceberg.raw.mongo__kill_events ke on m.match_id = ke.match_id and ke.time < 900
  left join iceberg.raw.mongo__rune_events re on m.match_id = re.match_id
  left join iceberg.raw.mongo__ward_events we on m.match_id = we.match_id
  group by m.match_id, m.duration
""")

# Pipeline
assembler = VectorAssembler(...)
scaler = StandardScaler(...)
pca = PCA(k=2, inputCol="scaled", outputCol="pca")

# Elbow method — подбор k
costs = []
```

## 19. Рекомендация героев на основе истории игрока (collaborative filtering)

**Тип:** spark + ml (рекомендательная система, ALS)

**Данные:**
- `match_players` — `account_id`, `hero_id`, `win` (рейтинг 1/0)
- Дополнительно: `kills`, `deaths`, `assists`, `gold_per_min`, `xp_per_min`

**Гипотеза:** на основе истории игрока можно рекомендовать героев, на которых у него наибольший win rate и лучшая стата, с учётом похожести на других игроков.

**Метод:**
- Implicit feedback: `preference = win ? 1 : 0`
- Explicit feedback: `rating = KDA + GPM/100 + XPM/100` (нормализованная оценка перформанса)
- ALS (Alternating Least Squares) матричная факторизация

```python
from pyspark.ml.recommendation import ALS

ratings = spark.sql("""
  select
    mp.account_id as user_id,
    mp.hero_id as item_id,
    (mp.kills + mp.assists) / greatest(mp.deaths, 1) + mp.gold_per_min / 100.0 + mp.xp_per_min / 100.0 as rating
  from iceberg.raw.pg__match_players mp
  where mp.win
""")

als = ALS(
    userCol="user_id", itemCol="item_id", ratingCol="rating",
    rank=10, maxIter=10, regParam=0.1, coldStartStrategy="drop"
)
model = als.fit(training)

# Топ-5 рекомендованных героев для игрока
recommendations = model.recommendForAllUsers(5)
```

## 20. Сегментация героев по пику и контр-пику (Matrix Factorization)

**Тип:** spark + ml (latent factor model + cosine similarity)

**Данные:**
- `match_players` — `match_id`, `hero_id`, `radiant_win`, `player_slot`
- Из Radiant Pick: `hero_id` для `player_slot < 128`
- Из Dire Pick: `hero_id` для `player_slot >= 128`
- Результат: `radiant_win`

3. Посчитать cosine similarity между векторными представлениями героев
4. Герои с наибольшей отрицательной корреляцией = контр-пики

## 22. Генерация саммари матча на естественном языке (LLM API)

**Тип:** llm (openai / llama / любой llm) + spark

**Данные:**
- Структурированные данные по одному матчу:
  - `matches` — победитель, длительность, game_mode
  - `match_players` — стата каждого игрока
  - `kill_events` — убийства (количество)
  - `tower_damage_events` — башни (количество, порядок)
  - `cs_events` (npcId=133) — Рошан (был ли, когда)
  - `gold_events` — максимальный разрыв по золоту
  - `streak_events` — максимальная серия убийств
  - `purchase_events` — ключевые предметы
  - `ability_learn_events` — порядок прокачки
  - `heal_events` / `hero_damage_events` — статистика урона/лечения
  - `rune_events` — контроль рун

**Гипотеза:** LLM может написать связное текстовое описание матча по его структурированным данным — как репортаж.

**Применение:**
- Автоматическая генерация хайлайтов для сайта/дашборда
- Саммари для каждого матча в enrichment pipeline
- Поиск самых интересных матчей (по тексту саммари можно искать "огромный камбэк" или "полный разгром")

**Метод:**
1. Для матча собрать JSON с ключевыми метриками
2. Отправить в LLM с промптом
3. Получить текст на 2-3 предложения с описанием матча
4. Сохранить результат рядом с данными в Iceberg или PG

```python
def build_match_summary(match_id: int) -> str:
    # Выбираем данные по матчу
    match = spark.sql(f"""
      select
        m.match_id,
        m.duration,
        m.radiant_win,
        (select count(*) from iceberg.raw.mongo__kill_events ke
         where ke.match_id = m.match_id) as total_kills,
        (select count(*) from iceberg.raw.mongo__tower_damage_events tde
         where tde.match_id = m.match_id) as tower_hits,
        (select min(time) from iceberg.raw.mongo__cs_events ce
         where ce.match_id = m.match_id and ce.npc_id = 133) as roshan_time,
        (select max(g.value) from iceberg.raw.mongo__gold_events g
         where g.match_id = m.match_id) as max_gold_lead
      from iceberg.raw.pg__matches m
      where m.match_id = {match_id}
    """).toPandas().iloc[0]

    # Топ игроков
    players = spark.sql(f"""
      select h.localized_name, mp.kills, mp.deaths, mp.assists,
        mp.gold_per_min, mp.hero_damage, mp.hero_healing
      from iceberg.raw.pg__match_players mp
      join iceberg.raw.pg__heroes h on mp.hero_id = h.hero_id
      where mp.match_id = {match_id}
      order by mp.hero_damage desc
    """).toPandas()

    prompt = f"""
Match ID: {match['match_id']}
Duration: {match['duration']}s
Winner: {'Radiant' if match['radiant_win'] else 'Dire'}
Total kills: {match['total_kills']}
First Roshan: {f'{match["roshan_time"]}s' if match['roshan_time'] else 'not killed'}
Tower hits: {match['tower_hits']}
Max gold lead: {match['max_gold_lead']}

Players:
{players.to_string(index=False)}

Write a 2-3 sentence match summary in Russian, describing the key moments.
If there was a comeback (team was behind but won), highlight it.
"""

    resp = requests.post(
        API_URL,
        headers={"Authorization": "Bearer $OPENAI_KEY"},
        json={
            "model": "gpt-4o-mini",
            "messages": [{"role": "user", "content": prompt}],
            "temperature": 0.3
        }
    )
    return resp.json()["choices"][0]["message"]["content"]

# Пример: "Radiant победил за 34 минуты. Ключевой момент — убийство Рошана на 22 минуте,
# после которого Dire взяли две башни и получили золотой разрыв в 8k.
# Shadow Fiend закончил с 15/3/10 и 800 GPM."
```


## 23. Поиск аномальных матчей через LLM (semantic search)

**Тип:** llm + embeddings (text-embedding-3-small или аналог)

**Данные:**
- Саммари матчей из кейса #22
- Embedding-вектор каждого саммари
- PG: `matches.match_id`

**Гипотеза:** можно искать матчи не по цифрам, а по смыслу: "матч где был невероятный камбэк", "игра с 4 рапирами", "самая длинная игра", "полный разгром за 15 минут".

**Метод:**
1. Сгенерировать саммари для всех матчей (LLM)
2. Посчитать embedding для каждого саммари (API эмбеддингов)
3. Сохранить вектор в Iceberg как `embedding array<float>`
4. При поиске — посчитать embedding запроса, найти ближайшие по cosine similarity

```python
from openai import OpenAI

client = OpenAI()

# Embedding для каждого саммари
embeddings = []
for summary in summaries:
    resp = client.embeddings.create(
        model="text-embedding-3-small",
        input=summary
    )
    embeddings.append(resp.data[0].embedding)

# Сохраняем embedding как колонку в матчах
df = spark.createDataFrame(
    [(m_id, emb) for m_id, emb in zip(match_ids, embeddings)],
    schema="match_id long, embedding array<float>"
)
df.writeTo("iceberg.stage.match_embeddings").append()

# Поиск: "матч где был невероятный камбэк"
query_emb = client.embeddings.create(
    model="text-embedding-3-small",
    input="матч где был невероятный камбэк"
).data[0].embedding

# cosine distance через spark
results = spark.sql("""
  select match_id,
    cosine_similarity(embedding, {query_emb}) as similarity
  from iceberg.stage.match_embeddings
  order by similarity desc
  limit 10
""")
```
